# Macro&Combo

## 範囲・根拠

- 種別: `/macro-combo`（`Macro&Combo` タブ）の runtime macro / runtime combo / runtime tapdance 編集ページ。binding の選択・閉じ方は共通の [binding editor](../modules/binding-editor.md)、履歴の保存先・復元は [version history](../modules/version-history.md) を参照する。
- combo editor と RAM/flash の保存契約は [Keymap の combo card](keymap.md) からも利用する。各ページの Save/Discard はそれぞれのページが保持する hook 状態を操作するため、タブを戻した際は再読込で最新値を確認する。
- この変更の確認: 2026-10-14、#262 の MAC-002 / MC-002 / MC-003 をコード・遅延/失敗 RPC 回帰テスト・Orca Demo（JA、1280×800）で確認。Demo は最初の Save → Refresh と同 macro 再選択 → 再編集後 Discard の値を比較。実機 flash / 電源断は未実施。共有 consumer の macro modal は同じ RAM debounce を使い、modal の終了/取消契約（BIND-019〜021）は変更しない。
- #213 の変更: 保存開始時の変更領域（macro の待機中/進行中 input write を含む）を記録し、利用可能という理由だけで成功通知の対象に含めない。成功通知と部分失敗の契約は MC-002、検証は page 回帰テストを参照する。
- 入口と利用者: 接続後の `Macro&Combo` タブ。macro subsystem `cormoran__runtime_macro`、combo subsystem `cormoran__runtime_combo`、tapdance subsystem `cormoran__runtime_tapdance` に応じて個別に編集と未対応案内を表示する。tapdance の独立した保存契約は TD-001〜006 を参照する。
- 確認: 2026-09-20、`857b934` + 作業ツリー。コード確認と Demo（Orca iPhone 12、390×844）で MC-001 / MC-R03 の mobile 選択・配置・状態表示を実測。実機 flash 再起動後の結果は未実施。

## 前提・状態

- 未接続では `Connect your keyboard to edit runtime macros and combos`。接続後でも subsystem ごとに unavailable になり、両方 unavailable なら編集リストを出さない。
- loading は各 hook の `isLoading`、combo と keymap を要する初回読込では `Loading combo data...`。ready は macro / combo list と detail、empty は `No macros yet. Create one above.` または空 combo slot の状態。
- locked は shared unlock gate を開く `Locked` button で、解除されるまで読み書き RPC の結果を保証しない。dirty は `Unsaved changes` と slot/global の StatusDot。`Save` は RAM の未保存変更または macro input の待機中/進行中 write があり、encoded-size/string conversion error がない時に有効になる。macro input の blur による RAM write 中も Save を受け付ける。macro input write がない macro loading、combo loading、Save/Discard/default reset 中は無効。
- macro/combo の編集 RPC は keyboard memory への変更を表す。両 hook の `save...` / `discard...` が何を flash にするかはこのページの範囲であり、設定全般の保存経路は [settings write](../modules/settings-write.md) を参照する。

## 代表ユーザーフロー

### F1: macro の作成、容量境界、保存（MAC-001/002/004、MC-002）

1. 接続して `Macro&Combo` を開き、表示された subsystem と macro list の初期値を記録する。
2. `Create macro` → Name を入力し blur → `Step` → `delay` を選び値を確定する。`Size` と `Unsaved changes` を確認する。
3. `Size/maxMacroBytes` を超える step を作ろうとし、error が表示され `Save` が無効であることを確認する。実機の最大値は固定しない。
4. error を解消し、string step に `immediate` を入力して別操作や待機を挟まず入力欄から最初の `Save` をクリック。未保存表示が消え、Refresh → 同 macro の再選択で文字列と新規 macro が保持されることを確認する。再編集後 Discard でも保存済み文字列へ戻ることを確認する。検証用に作った macro は Reset/Discard ではなく、意図を確認してから Delete する（Delete は確認なし）。

### F2: combo の位置、capacity、取消（COMBO-001/002/003/004、MC-003）

1. `New combo` を選び、empty slot がない場合の `No available combo slots.` を記録して終了する。
2. preview で二つの異なる物理 position を選び、`Positions` が昇順であることを確認する。1 position に戻すと validation error となり device write されないことを比較する。
3. binding editor で behavior を選び、layer と Advanced Options を変更する。binding editor の Apply/Close/Cancel 規則は共通仕様に従う。
4. `Discard` を選び、confirm がないこと、保存済みの combo list に復帰し selection が消えることを確認する。Cancel path は Reset menu に browser cancel control がないため該当なし。

### F3: global 保存と default reset の危険操作（MAC-004、MC-002/004）

1. Macro/Combo の gear を開き、`Tap ms` または `Timeout ms` を変更して StatusDot を確認する。
2. 直後の Save で debounce が含まれること、flash 保存後に dot が消えることを確認する。
3. `Reset every runtime macro and combo...` の native confirm を Cancel して値が不変であることを確認する。実機で承認する前に全 customizations が失われる文言を記録する。

### F4: 共通 Save の通知（MC-R04、MC-002）

1. 両 subsystem が利用可能な状態で、既存 macro の初期値を記録する。macro のみ変更 → Save → `Saved runtime macro changes.` を確認し、Refresh → 同 macro 再選択で実際の値を読む。元値へ復帰 → Save → Refresh → 再選択でも元値を確認する。
2. combo のみ変更した場合は `Saved N runtime combo changes.`、両方変更した場合は `Saved runtime macros and N runtime combo changes.` を確認する。未変更の利用可能 domain を通知に含めず、各値を Refresh/再選択してから元へ戻して保存・再読込する。
3. 遅延/失敗 RPC は回帰テストで確認する。前回成功後の次の Save は flush 待機中から前回通知を消す。macro 保存成功後 combo 保存が失敗しても全体成功・履歴 capture はなく、先に保存した macro の rollback はしない。Demo で失敗を注入しなければその条件を UI pass としない。

## 不変条件

- MC-I01: macro と combo を同時に detail 選択しない。両 list を交互に選び、右 pane と選択表示を比較する（S1）。
- MAC-I01: encoded size error の macro を Save しない。error 直後の Save disabled を確認する（S1/S4）。
- COMBO-I01: position 1 個、17 個、無効 behavior、slot range 外の draft を `setCombo` へ送らない（S5 `validateCombo`）。
- MC-I02: Discard 前に queued macro/combo write を flush しない。変更直後に Discard し、保存済み値に戻ることを確認する（S1/S4/S5）。

## エラーと復帰

- macro/combo/keymap error、string conversion、macro size error は上部 alert。combo RPC error のみ `Dismiss` がある。Dismiss は成功/保存の証拠ではない（S1）。
- macro input の RAM write 失敗後は Save を再クリックしても古い RAM 値を保存しない。同じ入力を再編集して write が成功するか、Discard で保存済み値へ戻してから再試行する。入力 write / 保存 RPC 失敗時は error を表示し、失敗した入力を保存済みとして扱わず、成功履歴を capture しない（MC-002）。
- read/write RPC error は hook が `error` と loading を戻す。値は楽観更新済みである場合があり、Refresh で device の現値を取り直す。retry は Refresh、または同じ変更の再入力。macro detail の読込失敗後も list entry があれば選択名と Delete は残り、削除 RPC を試せる。
- locked/cancel unlock は shared gate の `device is locked` message になる。unlock 後は page effect が macro/combo の error を clear して reload する（S1）。
- Save/default reset の domain 横断処理に transaction/rollback はない。Save は新しい試行開始時に古い成功通知を消し、部分失敗では全体成功を表示せず成功履歴も capture しない。既存の hook error を表示し、Refresh → 状態記録 → 必要なら Discard または再編集/Save で復帰する。先に成功した domain の保存は残る。

## 探索の観点

1. macro string の ASCII/shift 文字/変換不能文字、pool/encoded-size 上限、step count の増減。
2. combo の先頭/末尾 position、重複 toggle、2/16/17 positions、slot capacity、32 layer 境界。
3. debounce の直後に Save/Discard/Refresh/tab 往復して、古い write が復活しないか。
4. macro-only、combo-only、両 subsystem 不在、lock解除拒否、RPC failure で availability と error が混同されないか。
5. narrow layout と長い macro/combo name で preview と destructive control が操作可能か。
6. mobile の選択メニューが Refresh/Reset/Save と同じ高さ・同じ行に収まり、選択種別を小さな上段、項目名を下段に表示して長い名前を切り詰めるか。選択後に閉じて直下の編集 pane を表示するか。`Unsaved changes` の文字は隠れても status dot と各 menu item の dot が残るか。

## Runtime tapdance

明示要求: Macro & Combo 内で runtime tapdance を編集する。プロトコルは [開発中 firmware PR #1](https://github.com/cormoran/zmk-feature-runtime-tapdance/pull/1) の `22d8dbd3eccdc72743dcb3f647c23c5b2acaa0bb` に合わせる。根拠は [TapDanceEditor](../../../src/components/macroCombo/TapDanceEditor.tsx)、[useRuntimeTapDance](../../../src/hooks/useRuntimeTapDance.ts)、[protobuf](../../../proto/cormoran/runtime_tapdance/runtime_tapdance.proto)。Macro/Combo の Save、Discard、default reset、version history は tapdance を含まない。

| ID     | 契約                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TD-001 | 接続中に独立した Tapdance セクションを表示する。`cormoran__runtime_tapdance` がない場合は unavailable の案内。macro/combo の両方がない firmware でも tapdance があれば編集できる。初回とタブ復帰時に全 slot を読む。読込中・保存中は操作を無効化する。失敗はセクションの alert に残し、Refresh で再試行する。                                                                                                                                                                                                                                                                     |
| TD-002 | `Tapdance slot` で firmware が返した範囲から選び、Single / Double / Triple タブから標準 binding selector を開く。再帰する runtime tapdance behavior は候補から除外する。Single は必須。Double は省略可能だが Triple には Double が必要。無効な下書きは保存できない。                                                                                                                                                                                                                                                                                                              |
| TD-003 | `Save tapdance` の前は component 内の下書きで、デバイス書込みはない。`Discard edits` は最後に読み込んだ/書き込めた状態へ戻す。slot 切替、Refresh、modal の Close/Escape/外側クリックはローカル下書きを破棄する。ページ移動で保持された main editor の下書きは、タブ復帰時の再読込で破棄する。保存は各 action を `persist: true` で個別に flash へ書く。成功後 `Tapdance saved to keyboard.`。途中失敗は一部保存済みの可能性と再試行を案内し、下書きを残す。成功済み action を含め再保存できる。Double/Triple の削除は Triple から、追加は Single から行い、中間状態も有効にする。 |
| TD-004 | `New tapdance` は未使用かつ読み込んだ keymap に参照のない空 slot の modal を開く。空 slot がなければ無効。`Edit tapdance` は選択 slot の modal を開く。新規・編集とも保存成功後に閉じ、対象 slot を選ぶ。保存せず閉じても書込みはない。編集 modal と main editor の下書きは独立し、modal 保存後は main editor を保存結果に合わせる。                                                                                                                                                                                                                                              |
| TD-005 | `Tapdance interval (ms)` は整数 1〜2000。`Save interval` で全 slot 共通の間隔を flash へ保存する。`Delete tapdance` は対象 slot を利用するキーが動作しなくなる確認を経て `remove(persist: true)` を送り、slot を空にする。失敗は alert と再試行。キー割当自体は削除しない。                                                                                                                                                                                                                                                                                                       |
| TD-006 | 同じ slot を使用する全 layer の runtime tapdance binding を数えて共有注意書きを表示する。ページでは全参照件数、キー選択では現在の割当を除く他の参照件数。keymap 未取得時は件数不明としゼロを断定しない。これは読み込んだ keymap の件数で、macro 等に内包された参照は含まない。                                                                                                                                                                                                                                                                                                    |

代表フロー: TD-001/002/003: slot と Single の初期値を記録 → Single を変更 → Discard edits で復帰 → 再変更 → Save tapdance → Refresh → 同 slot の値を照合 → 元値を保存し Refresh で復帰確認。TD-004: New tapdance → Single を設定 → Close → slot が空のまま → 再作成して保存 → Refresh → Delete tapdance の取消/承認。TD-005: 間隔 0/2001/小数では保存不可、初期値から有効値へ保存・Refresh・復帰。TD-006: 同じ slot を複数キー/複数 layer で使用して件数と共有更新を確認。

検証境界: codec を通した RPC simulator と hook の回帰テストは実機の tap 検出・flash・電源断後の永続性を証明しない。Demo は同じ接続内の再読込を検証できる。実機と全テーマの UI 判定は実施範囲を PR に記録する。
