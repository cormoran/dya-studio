## 前提・状態

接続済みまたは Demo の Keymap が対象。Keymap 読込・Save/Reset/Discard 中は入口を無効化する。Studio locked 時は既存の unlock 操作を優先し、Save と共有メニューを隠す。メニューは画面幅内に収まり、長い一覧はスクロールする。狭い画面の入口はアイコンと accessible name を維持する。

未認証・認証読込中はアカウント/現在/所有一覧/新規保存を出さない。OAuth client 未設定では login を無効化し理由を表示するが、file/search は利用可能。認証後メニューを開くと keyboard snapshot と識別子を読み取る。Abyss の layout resolve・所有一覧・取得済み record 本文はメニュー component のメモリに保持し、閉じる→再表示・同じ record の再 preview では再利用する。ブラウザ reload/unmount で失われ、localStorage/IndexedDB には保存しない。更新 icon は再取得し、接続・認証・username 変更で cache を破棄する。作成/更新成功時は該当 record と一覧を無効化して更新する。`Loading...`（読み込み中）の左には回転する loading icon を表示し、読込完了で文言とともに消える。icon は装飾扱いとし、status の読み上げは文言で行う。`Loading...` 中は書込み系操作を無効化する。空一覧とエラーを区別する。

## 代表ユーザーフロー

1. Demo の Keymap でメニューを開き、未認証では login/search/file のみ、閉じる→開くが可能なことを確認（IE-013/014）。
2. ファイル保存→JSON を別名で保持→キーを編集→ファイルから反映→visual/code diff で変更先を確認→キーボードに反映→確認 Cancel、編集が残ることを確認。再度反映を確定し、ページ内 Reload 後に元の値が戻ることを確認（IE-017/020/021/022）。Demo は実機 flash の証拠ではない。
3. 認証環境で current/所有一覧の行を選択して preview を開き、強調キーの tooltip、変更一覧 All layers→単独 layer、Code diff タブ、比較方向を確認。Upload from keyboard to Abyss→Abyss のキーマップを更新→確認 Cancel→再度更新→確認 Save で同じ Abyss record を再取得して確認（IE-015/016/026/027）。
4. Include を全 ON→キーマップ OFF→module 1つ OFF と変更し、visual/code diff と変更数を比較。方向切替→確認 Cancel 後も選択維持、閉じる→再度 preview で全 ON。global/layer の field path と変更前後を確認する。実行で除外部分が保持されることは Demo/検証用アカウントの適用先 readback と比較して別途確認（IE-028/027）。
5. 新規保存で private/public を選び保存、一覧更新/record 再取得、sign out 後 cloud section 非表示を確認（IE-019/023）。所有キーマップの行右側には公開済みの場合のみ `public`、Preview header のタイトル左側には公開状態に応じて `private` / `public` が表示され、file preview には表示されないことを確認（IE-029）。外部サービス書込みは検証用アカウントでのみ実施。
6. identity RPC の新旧 firmware を比較。対応機は適用後 identifier の get readback、編集後も同一、再接続後の判定、file 反映後 empty を確認。未対応機は注意表示と file/cloud 機能の継続を確認（IE-024）。

- IE-I01: 読込中・保存中・blocked preflight では二重書込みを開始しない（S3）。
- IE-I02: cloud/file 保存は keyboard binding を書かない。cloud 保存後の identity metadata 書込みは別の副作用（S3/S4）。

## エラーと復帰

auth/list/read/export/import のエラーは alert に残る。menu は Refresh または同じ操作で再試行、modal は Cancel で既存 preview へ戻る。更新競合の場合は preview 自体を閉じ、同じ record 行を選択して新しい snapshot を取得してから再確認する。エラーにも preview を閉じて開き直す手順を示す。read error で過去の snapshot を書込みに流用しない。401 は再 login が必要。新規作成成功後の metadata/list error は record 作成を再実行せず menu に残す。identity setter の成功 acknowledgement と get readback がない場合は注意する。

新規保存・更新はクリック時に空 tab を確保し、Abyss API の保存成功後だけ対象ページへ遷移する。保存前の失敗・競合では空 tab を閉じる。popup が block された場合も保存は継続し、メニューに `Open on Abyss` link を残す。URL は設定された Abyss instance を使う。保存後の identity/list エラーでも、保存済み record のページと link は利用可能。

adapter は逐次書込みし原子的 rollback はない。途中失敗は混在状態になり得るので再読取してから再確認する。Confirm 前の検査と実際の書込間の外部変更を server-side CAS で防ぐ契約はない。
