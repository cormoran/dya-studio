## 前提・状態

- Demo はトップの `Try Demo Mode` → `Keymap`。表示される layer 名、キー数、初期 binding を観測して記録する。初期値を固定して探さない。
- 位置の表記を混同しない。preview と selector header の key position は 0 始まり。キーボード上の文字が同じでも position で区別する。
- selector の header は `layer · Key position 0: binding` のように、preview と同じ0始まりの位置と、開いた時点の binding を示す。floating / sheet のheaderにはbehaviorの説明を表示しない。
- loading: 進行ラベルを表示。キーが先に見えても背景の behavior/layer 読込が終わるまで待つ。Reload は読込中無効。
- ready: layer ボタン群と keyboard preview。dirty: `Unsaved changes`、Save 有効。保存済みは `Saved`（初期値から変更された保存済み binding は別の色/tooltip）。
- locked: Save/Reset に代えて `Locked`。閲覧/Reload は可能。編集は共有 unlock prompt を経由する。解除キーの配置図と汎用説明へのフォールバックは [SESSION-015](../modules/device-session.md#ロック解除キー案内session-015) に従う。Demo で任意の lock/RPC failure を起こす UI は未確認。
- unsupported: Stream は対応時のみ。物理 layout の select は複数 layout 時のみ。sensor rotation 非対応は警告と導入リンク。空の layer 一覧ではキー配列・保存状態・sensor 設定を表示しない。layer item がないため並べ替え・Rename・Delete は表示しない。Add/Restore は既存の容量・削除済み ID 条件に従う。Reload と keymap/combo 全体の Save/Discard は既存の loading/dirty 条件に従い、空であることだけでは無効にしない。専用 empty メッセージはない。
- combo subsystem があるときだけ sensor 設定の下に `Combos` card を表示する。keymap の全読込後に combo を読込む。未対応時は card と preview の combo 表示を出さない。combo の RAM 編集は keymap binding と別だが、Keymap header の Save/Discard/Reset が両方の保存・復帰境界になる（S1/S7）。

## 現行の機能仕様

ページタイトル直下の説明文と主操作の狭幅配置は[共通画面 SHELL-022](../modules/app-shell.md)に従う。幅640px未満では説明文を非表示にし、操作はタイトル行から配置して必要な分だけ折り返す。

ページ見出し左の装飾アイコンは[共通画面 SHELL-021](../modules/app-shell.md)に従い、幅640px未満では枠ごと非表示、640px以上では表示する。

KM-025: 主要操作の tooltip は、Stream が ON の間は押したキーボードのキーをハイライトすること、Reset が以前のバージョンや初期値に戻す入口であること、Save が現在適用中のキーマップを再起動後も維持するための保存であることを説明する。レイヤー名変更・追加・削除と editor の dialog/floating 切替も対象や表示結果を説明し、短いボタン名・accessible name は維持する。根拠: 2026-10-17 ユーザー要求、KeymapPage。文言変更のみで操作・保存境界は変更しない。

KM-024: 物理レイアウトの Trackball・Touch Pad・Encoder・custom module は、全テーマで通常キーと同じ背景・枠・文字色を使う。表示専用のためhoverしても背景・枠・文字色は変化させない。Popでは通常時の枠線を表示しない。形状・アイコン・ラベルで種類を示し、無効moduleの半透明・破線・disabled表示は維持する。表示専用で選択・binding編集は行わず、hoverの詳細tooltipを維持する。根拠: [PhysicalLayoutModule](../../../src/components/PhysicalLayoutModule.tsx)、S5。2026-10-17ユーザー要求。

KM-017: ページ全体の横スクロール防止と主要操作の狭幅表示は[共通画面 SHELL-009/010/011](../modules/app-shell.md)、floating editor のviewport内配置は[binding editor BIND-011](../modules/binding-editor.md)に従う。モバイルでもlayer切替列とプレビューの個別横スクロールを保持し、bindingの座標・保存契約は変更しない（S1/S5、2026-09-20ユーザー要求）。

## 代表ユーザーフロー

削除済みlayerの復元メニューもviewport端から8px以上を確保し、高さを超える項目はメニュー内で縦スクロールする。外側タップ/Escapeで閉じ、項目選択まで復元を実行しない（KM-011/017、S1のPopover）。

### F1: 単一キーの変更と保存（KM-002/007/009）

1. Demo → Keymap。layer 名、先頭キーの label と tooltip の binding、`Saved` 状態を記録。
2. 先頭キーをクリック。既存の behavior が key press なら、元と異なるキーを selector の keyboard から選ぶ。必要なら behavior を key press に変更し、parameter のキーを選ぶ。表示された実ラベルを報告に書く。
3. selector が閉じ、対象キーの表示と `Unsaved changes` を確認。別位置のキーが変わっていないことも比較。
4. Save → `Saved`、Save 無効を確認。Reload → 選んだ binding が維持されることを確認。
5. 元 binding に戻して Save。初期値が不明なら勝手に reset せず残存状態を記録。

### F2: 連続編集の境界（KM-003/004/005/006）

1. キーを開き `Floating mode`。header の対象 `Key position` を記録し、behavior の説明を表示しないことを確認。
2. Auto advance の押下状態を確認し ON にする。異なる binding を選ぶ → `Key position` が次へ進み、selector は開いたまま。次キーが上側workspaceやpreviewの表示範囲外になる配置でも続け、必要な縦/横scroll後に選択キー全体が見えることを確認する。すでに見えるキーではscroll位置が変わらず、focusはeditorに残る（KM-027）。
3. OFF にして別 binding を選ぶ → `Key position` が変わらない。Next → 次の `Key position`（binding は適用しない）。
4. preview の最後のキーを選び、Next 無効を確認。ON で適用 → selector が閉じ、layer は変わらない。
5. 再度開いて mode を往復し、floating の状態で Escape → 未適用値が書かれていないことを確認。modal の Close/Escape は適用して閉じるため取消として使わない。編集は Reset → Discard で破棄し、元の mode/auto advance を復帰。

### F2a: モバイルsheetの配置と復帰（KM-026 / BIND-025 / SHELL-023）

1. DemoのKeymapを390×844で開き、layer・binding・modeを記録する。キーを選びSheet modeへ切替える。上側はlayer選択とpreviewから始まり、app header/tab/ページ見出しが消えること、下側sheetの高さがviewportの45%で両領域が重ならないことを測定する。
2. 上側で別キーを選び、sheetの対象が更新し、表示だけではbindingが書き換わらないことを確認する。layerを変えると既存の契約どおりsheetが閉じ、次にキーを選ぶと新layerの対象をsheetで開くことを確認する。上下それぞれのscrollとsheetのClose/モード切替に到達できること、headerをドラッグしても位置が変わらないことを確認する。
3. 639px/640pxを往復して通常floatingとsheetが切替わり、対象とdraftが維持され、header/tabの表示とmain高さが復帰することを確認する。320pxと短い横向きviewportでも上下の領域を確認する。
4. Close/EscapeとDialog modeへの復帰を別々に試し、上側のheader/tab/Save等の操作が戻ることを確認する。previewのcomboにも同じ配置を適用し、通常キーとの切替でsheetが1枚だけであることを確認する。元のmode・layer・bindingへ戻す。

### F3: layer と取消（KM-001/008/010/011/012）

1. 初期 layer 名と保存状態を記録し、`Edit layers` を開き、先頭 layer の handle で左矢印を押して順序不変を確認。対象 item の Rename を開き仮名を入力、Cancel → 元の名前・保存状態。別の仮名で Rename ボタンを押し、更新名と `Unsaved changes`、Save → アプリ内 Reload 後の同じ名前と `Saved` を確認する。再び開いて Enter でも変更し、同じ保存・readback を行う。元名で Rename → Save → Reload して復帰する。

Rename の失敗変形: Demo で ASCII 32文字（advertised max length）を入力して Rename → エラー・dialog と入力の保持・元名と保存状態の不変を確認。短い名前に修正して Rename / Enter を再試行し、成功後に保存・Reload で readback、元名に戻して保存・Reload する。エラー時は閉じて再オープンする変形も確認する。

2. binding を変更、Reset → Discard の confirm をキャンセル → dirty のまま。再度 Discard を承認 → 保存値。
3. 対応していれば Reset to initial state の確認を開く。警告を読み Cancel → keymap 不変。実機では承認しない。
4. 追加対応の Demo で Add → 新 layer の選択と `Unsaved changes` を確認。新 layer を選んだまま Reset → Discard を承認 → 追加が消え、末尾の残存 layer が選択され、キー配列・`Saved`・対応時の sensor 設定が表示されることを確認。Save は無効、並べ替えの端と Rename/Delete の有効条件も確認する（KM-008/011、[#256](https://github.com/cormoran/dya-studio/issues/256)）。
5. アプリ内 Reload → 残存 layer の選択・キー配列・保存状態・sensor 設定を再確認。編集を終了し、別 layer を選んで戻り、正しい選択と binding を確認。空の一覧と空からの復帰は通常 Demo UI で作れないため、一覧差替えの自動テストで確認し、browser pass と混同しない。

## 不変条件

- KM-I01: 別の layer/position に binding を誤適用しない。前後 2 キーと別 layer を比較（KM-R01、S1）。
- KM-I02: floating の失敗時は選択を進めない。先行 RPC 完了で後から選んだキーを移動させない。二重適用を抑止する（S1 applyingBindingRef/selectionRevision、S4）。通常 Demo の即時応答だけでは検証できない。
- KM-I03: mode 切替・矢印・floating の Escape だけで draft を書き込まない（S4）。modal は変更済み draft を Close/Escape で適用するが、無変更 Close/Escape では書き込まない（S3 handleOpenChange）。
- KM-I04: OS Layout の変更だけで device binding を変更しない（S1 の説明、表示用 context）。
- KM-I05: editor header の layer/position/binding は現在選択中のキーと一致し、同じ binding の別キーを区別できる（KM-R04/KM-019）。
- KM-I06: combo preview の対象と editor slot は一致し、非隣接 badge はキー binding のクリック対象を奪わない。combo の番号は card と preview で同じ slot順の 1 始まり、header Save/Discard は keymap と combo のどちらかが dirty なら両方を扱う（KM-007/008/020〜022）。

## エラーと復帰

- RPC/保存失敗: keymap の `role=alert`、floating 内にも error。S2 の通常エラーは約 5 秒で消去、成功 RPC でも消去。消えたことを成功と解釈しない。値・dirty 状態を再確認し、再試行/Reload で確認。
- floating の適用失敗は開いたまま同じキーを保持。modal は S3 が `onSelect` 後に直ちに閉じる経路があり、失敗しても開いたままとは保証しない。
- Rename は hook の boolean 成否を待ち、失敗・例外では dialog 内に再試行を促す alert を保持する（KM-012）。入力を修正して Rename / Enter、または Cancel/閉鎖して再オープンできる。ページ側の hook error の約5秒消去とは独立しており、消失を成功と扱わない。
- Reset default は途中失敗なら未保存の部分変更が残り得る。成功と表示されなければ Reload で現状確認、必要なら Discard。原子的 rollback を保証しない。
- physical module preview 読込失敗は黄色の警告。Stream error は別 alert、Dismiss で消せる。実機/RPC error 注入は今回の通常 Demo 手順外。
- combo RPC error は `Combos` card の alert に表示する。無効 draft は editor の validation error に表示して書かず、修正して header Save を再試行できる。keymap reset と combo reset/save は transaction ではないので、途中失敗時は部分変更を想定して Reload と dirty/alert を確認する（S7）。

## 探索の観点
