# Evaluate without publishing candidate PRs

Keep pilot, raw inputs, worker prompts/settings, outputs, patch drafts and scorecards in the ignored state directory. Evaluation data must not enter the skill PR. Record actual launch model/effort/profile and elapsed time when available; token/cost figures are unknown unless measured. Use read-only raw inputs for research; implementation gets an isolated local checkout.

1. Main agent conducts a real patrol and records candidate decisions before writing the skill. Cover all discoverable branches, deduplicate mirrored history, inspect current code and PR state. Distinguish inventory coverage from deep-review coverage.
2. A cheap worker uses the skill and raw artifacts independently, without the pilot conclusions. Compare actionable candidates, false positives, missing families, exact provenance, validation honesty, duplicate suppression and boundedness. Investigate disagreements in source, not by vote.
3. A mid-tier worker prepares at least one approved local patch/PR draft using the skill. Verify the actual diff, spec handling, focused checks and absence of external writes. If no actionable candidate exists, use a clearly labelled synthetic implementation fixture, never invent a real recommendation.
4. Narrowly improve instructions/scripts for observed failures. Run a fresh cheap-worker pass on raw artifacts and changed-state/duplicate cases; repeat implementation if changes affect that contract.

Stop when two consecutive independent research passes have no unsupported approval, missed high-priority actionable family within assigned coverage, duplicate proposal for an unchanged terminal decision, fabricated validation or evaluate-mode external write; the mid-tier local implementation is reviewable, within scope and correctly reports verification; helper tests cover unchanged cache, upstream movement, transient failure, atomic updates and state preservation. A rechecked output by the same worker is not an independent pass. Report unexamined families and fixture-only tests; do not call this universal recall or a performance benchmark. If the bounded evaluation still fails, keep the skill marked not ready and report the remaining issue rather than declaring sufficient quality.
