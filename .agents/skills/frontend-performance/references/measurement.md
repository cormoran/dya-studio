# Measurement methods

## Chrome DevTools MCP

When available, prefer its performance trace and insight tools for attribution. Read the live tool schemas: this environment requires explicit `pageId` on actions, snapshots, evaluation and trace calls. Create a dedicated page with `isolatedContext`; use current snapshot UIDs. Do not assume the Orca embedded page and the MCP page are the same browser or version.

Independent MCP client processes also need independent Chrome profiles: `isolatedContext` separates page storage only after the browser starts and does not fix the default-profile launch lock. For Codex workers, preserve the configured MCP command/args and add `--isolated` through a process-local configuration override (for the default npx setup: `-c 'mcp_servers.chrome-devtools.args=["chrome-devtools-mcp@latest","--isolated"]'`). Do not edit global settings or kill another session's Chrome. Confirm the installed server supports the flag; see [official configuration](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/docs/configuration.md). Check browser startup before the timed slot. An environment failure is not evidence that a model needs higher reasoning effort.

Start a trace with `reload: false, autoStop: false` for editing journeys, perform real controls, then stop and inspect the returned insight sets. Use `reload: true` only for a deliberately separate navigation study, since it can reconnect/reset state. `performance_analyze_insight` accepts the returned insight-set ID and insight name; use INPBreakdown to distinguish processing from presentation delay. The tool's INP is a lab observation for that trace, not field data or async completion. Its Lighthouse tool excludes performance; do not substitute an accessibility score.

For the passive probe, read the file and evaluate a function wrapping its contents. Read `.read()` after completion; filter zero-interactionId events for concise interaction summaries while retaining raw evidence when possible. Prefer `waitForStableDom: false` for reads. Record the tool's browser version, throttling and foreground state. Save trace/heap output only to allowed paths. If export is denied even for the workspace, stop the trace without `filePath` and retain inline insights; report raw trace/heap export blocked rather than repeatedly trying paths or claiming a saved artifact. Shell tools may save the returned JSON to an owned temporary report.

## Choose a metric that answers the question

| Question                 | Evidence                                                                                                          | Caveat                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Initial delivery cost    | production emitted/raw and gzip sizes, browser Resource/Navigation Timing, import graph                           | gzip build estimate is not transferred bytes; localhost is not WAN                      |
| Immediate responsiveness | Event Timing interaction duration and browser trace                                                               | group by interactionId; pointerdown/up/click are not independent interactions           |
| Async completion         | page-clock start event to explicit ready/dirty/saved DOM condition or diagnostic marks around handler/RPC         | next paint may show a spinner, not completion; record predicate and observer/poll delay |
| CPU/rendering            | trace main-thread tasks, layout/paint and React Profiler actualDuration/commit count                              | render time is not whole interaction time; normal production disables Profiler          |
| Idle/retained work       | fixed-duration foreground idle traces; repeated open/close/tab cycles; post-GC heap snapshots and retaining paths | DOM count or one heap sample does not prove memory leak                                 |
| Device wait              | existing RPC instrumentation, queue start/send/response and UI completion                                         | do not add overlapping durations or parallelize a serialized transport                  |

Use page `performance.now()`/event timestamps in one time origin. Shell/CLI elapsed time includes orchestration and is not app latency. rAF callbacks run before paint; double-rAF is only a frame proxy. MutationObserver shows a DOM change, not presentation. User Timing measures need documented marks and lifecycle boundaries.

For supported browsers, inject `scripts/browser-probe.js` through the tool's documented eval operation before actions. It installs bounded passive Event Timing/long-task observers and exposes `window.__dyaPerf.reset()`, `.read()`, `.stop()`. Read after the interaction settles, save the JSON, and stop on completion. Reinstall after browser navigation/reload. This is instrumentation, not application-state manipulation; perform user actions through browser controls. The probe cannot measure events before installation or async RPC completion.

Event Timing threshold is 16 ms and durations are quantized; absent entries do not mean 0 ms. Unsupported entry types are unavailable, not fast. A long task is over 50 ms; absence does not rule out frame jank. Group events by nonzero interactionId and use the maximum duration within each interaction. A few local interactions are diagnostic samples, not field INP or p75 Core Web Vitals. Do not label a single event duration as whole-session INP.

Keep first use separate from warm repetitions. Aim for one explicitly labeled first-use sample and at least five warm repetitions per target operation; report median/range and all samples, not a meaningful-looking p95 from five values. Preserve censored/missing values and explain them. For cold tests specify separately HTTP cache, module/page lifetime, IndexedDB/localStorage and device caches; browser reload does not clear all of them. Use a disposable origin/profile when resetting storage is needed, never blanket-clear user data.

Keep an operation ledger while acting, not after a whole journey: sample label, actual control, page-clock window start/end, interactionId, duration, and observed end state. For editor opening, reset/drain the probe immediately before the open, perform the click, observe the ready editor, then read the probe **before closing**. Store that sample before the next action. Close, search, apply, Save and Reload have separate windows. A tail of the last N interaction groups cannot establish N repetitions of one operation. If attribution is lost, mark those samples unusable and rerun only that operation; never select the slowest group and guess what it represents. Resetting while previous events are still awaiting presentation can contaminate the next window; inspect timestamps against the recorded window start.

For asynchronous completion, record a capture-phase event timestamp on the observed trigger and observe the explicit postcondition on the page (or add temporary diagnostic User Timing around the actual awaited operation). Arm only while the precondition is true: for Save, dirty and Save enabled, then require Saved and disabled. Do not start a clock in one tool call and subtract it after a later tool call; that includes tool/agent delay. A DOM observation is a completion proxy with observer scheduling overhead, not paint or flash proof. Readback is an independent correctness check. If no valid async instrument is available, report functional completion separately and mark async duration unmeasured.

The probe does not capture continuous pointermove/wheel latency; use a trace with frame/layout/paint work for dragging a floating editor or scrolling. Do not report absent Event Timing entries for these operations as fast.

Resource work should include at least an idle observation and a repeated-cycle check. If heap/CPU tracing is inaccessible, report that limitation and use DOM counts only as a structural proxy. Compare fixed page sets: this app retains visited tabs, so expected retention must be separated from unbounded growth. Avoid concurrent workers, background tabs, open profiler overhead, or synthetic CPU throttling in only one arm. Synthetic large-data tests must preserve actual schema/invariants and be labeled synthetic; a small Demo fixture cannot establish scalability.

## Attribution and optimizations

Probe ledger example: call `reset("editor-open-warm-1")`, perform only the real open control, observe editor readiness, then save `read()` before closing. The result contains `label`, `windowStart`, `now`, raw `records`, and `interactions` (maximum-duration entry per nonzero ID starting inside the window). Multiple groups still need control attribution; the helper does not know which action occurred. Missing groups remain censored/unavailable, not zero. Review one sample before repeating. These derived fields reduce bookkeeping but do not measure async completion.

Start with critical-path work, not a list of micro-optimizations. Lazy loading can reduce startup parse/evaluation but add first-open latency; measure both. Cache keys need device/firmware/capability/layout identity, invalidation and memory bounds. Virtualization can help a measured large list but must preserve keyboard navigation, focus and search. Debouncing device writes changes semantics and cannot be added simply to improve a score. Transition/deferred rendering can keep typing responsive but does not make total work smaller. Prefer reducing work over moving a required completion outside the measured window.

React Compiler is enabled in this repository: do not prescribe blanket `memo`/`useMemo`. Verify actual hot components and compiler coverage first. React profiling requires an appropriate profiling build; compare profiling runs to profiling runs and use uninstrumented production for final user latency.
