# Theme design

各テーマのコンセプトと変更時の判断基準をまとめる。選択・保存・フォント読み込みの動作は [SHELL-005](../../docs/spec/modules/app-shell.md)、利用可能なテーマ一覧は [themes.ts](./themes.ts) を参照。

| テーマ                  | コンセプト                                              | 主な実装                           |
| ----------------------- | ------------------------------------------------------- | ---------------------------------- |
| [Light](./light.md)     | 青みのある白と、涼しげなアクセント                      | [共通CSSのlight定義](../index.css) |
| [Dark](./dark.md)       | チャコールの面と、鮮やかなネオンアクセント              | [共通CSSのroot定義](../index.css)  |
| [Pop](./pop.md)         | クリーミーパステル × ポップ。くすませない軽さと柔らかさ | [pop.css](./pop.css)               |

LightとDarkの説明・調整基準は既存実装の視覚方針を保つための整理であり、今回新たに合意したデザインではない。PopとNeutralは2026-10-17のユーザーとの調整で最終的に採用した方針を記録している。途中で戻した配色や未採用の提案を調整基準にしない。パレット表は役割を説明する代表色であり、全CSS値の複製ではない。仕様・実装・意図に不一致があれば記録し、見つかった不一致を文書だけで正当化しない。

## 共通の重要ポイント

- 全テーマのスクロールバーは縦・横とも4px。ページ本体・浮動メニュー・内部スクロール領域・Homeの商品ギャラリーに共通適用する。WebKit scrollbar非対応ブラウザでは`scrollbar-width: thin`を使う。色は各テーマの定義を維持する。

- テーマ専用の変更は対応するroot classに限定する。別テーマへ切り替えた後に色・フォント・装飾を残さない。共有CSSの変更は全テーマへの影響を確認する。
- 背景・カード・入力・キー・浮動メニューの役割を区別する。同じ色にして境界や押せる領域を消さない。枠線用tokenを背景に流用すると意図しないくすみが出るため、各テーマの面の役割と照合する。
- 通常・選択・hover・focus・disabledと、成功・警告・エラーを区別する。意味は色だけでなく文言・アイコン・状態属性でも伝える。表示専用のTrackball・TouchPad・Encoderは各テーマの通常キーと背景・枠・文字色を揃え、hoverで色を変えず、詳細tooltipを維持する。
- Light・Dark・Neutralは既存のInter/system系UI書体、コード等は既存の等幅書体。Popのみ丸ゴシックを必要時に非同期で読み込み、入力・キー刻印・コードの例外を維持する。フォント取得に失敗しても操作を止めない。
- テーマ変更は表示設定であり、デバイス設定への書込みを伴わない。復元・未知値のfallbackはSHELL-005に従う。
- レビューでは [全テーマの一貫性確認](../../docs/spec/EXPLORATORY_TESTING.md#テーマの一貫性確認) に従い、この一覧から各テーマの文書を読んで実画面と比較する。値・境界・書体の証拠と未検証範囲を分け、確認後は元のテーマへ戻す。

テーマを追加・調整したら、対応する個別文書とこの一覧を更新する。共通の操作仕様を各テーマ文書に複製しない。
